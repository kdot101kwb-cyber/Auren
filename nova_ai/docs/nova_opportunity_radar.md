# NOVA Opportunity Radar: income-first GitHub tools

## Objective
Prioritize small, testable income experiments and GitHub projects that reduce delivery time. Do not optimize for stars alone.

## First shortlist
1. OpenHands — coding and delivery support; isolate code execution.
2. Hermes Agent — reusable skills and learning workflows; review persistence and permissions.
3. Browser Use — browser research automation; respect site terms and require approval for submissions.
4. n8n — small-business workflow automation; review its fair-code license before commercial use.
5. MoneyPrinterTurbo — short-video production prototype; validate media rights, provider cost, and platform eligibility.
6. Firecrawl — public-web research extraction; review hosting cost, license, and source terms.
7. Dify — prototype a narrow AI workflow; model and hosting costs must be explicit.
8. Agent-Reach — research discovery across accessible platforms; verify source support and policy compliance.

The list is a candidate catalogue, not evidence that these projects are installed, currently license-cleared, or tested in NOVA. Re-check the exact revision, license, security advisories, dependencies, resource requirements, and recent maintenance before adoption.

## Zero-budget income experiments
- Original niche short content: publish a small batch, measure retention and audience signals, and only then evaluate monetization eligibility.
- Small-business automation: make a demo that saves time, validate one customer problem, and sell a scoped pilot.
- Niche research report: produce a source-backed sample and validate a buyer before expanding.
- One-purpose micro-tool: build the smallest useful prototype and seek feedback before adding features.

No income is guaranteed. Platform eligibility, Sudan access, payout routes, taxes, licensing, and service fees must be verified for each actual path. The ranking intentionally returns no revenue forecast until demand evidence exists.

## Simple next-step plan

The callable now returns one compact plan alongside the ranked shortlist:
- one best-fit income experiment for the available daily minutes;
- one deliverable and first action;
- a short validation checklist including Sudan access and payout-method checks;
- up to three GitHub candidates, all clearly marked as unverified;
- three practical actions for today and a stop rule that prevents spending before demand is shown.

This is intentionally not a new crawler or a second scheduler: the existing revenue engine and opportunity-monitor modules already cover scheduled work/reporting patterns. The plan does not send outreach, install code, publish content, or claim current eligibility. If no experiment fits the time budget, it returns no selected experiment rather than inventing one.

## Scoring
Rank candidates using fit to income/research goal, integration effort, upfront cost, time to first market signal, reusable skills, risks, and evidence quality. Popularity is only a discovery signal. Keep `licenseVerified` and `testedInNOVA` false until real checks are recorded.
